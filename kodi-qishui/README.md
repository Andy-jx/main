# 汽水音乐 · Kodi 视频版

目标：在 Kodi 里完成汽水音乐登录、浏览和播放，重点做成适合电视端的**歌曲视频 / 听歌视频模式**。

## 当前 0.1.0

已实现 Kodi 前端：

- Kodi 内发起扫码登录并显示二维码
- 登录 sessionid 只保存在 Kodi 本机 profile
- 听歌视频 Feed
- 混合搜索：歌曲 / 视频 / 歌单
- 我的歌单
- 我的收藏
- 推荐歌单
- 歌单详情
- 视频详情解析 + Kodi 直播放
- 音频直播放（仅当上游返回 Kodi 可直接播放的音频 URL）
- 桥接服务健康检查
- 支持 Kodi 与桥接服务分处同一局域网的两台设备

## 为什么先用桥接服务

汽水音乐的二维码登录、PC 搜索、App Feed 和播放接口变化比较快。0.1 版把易变的上游协议放到独立的 `qishui-api` 桥接层，Kodi 端只做电视 UI、登录态保存和播放。

这样测试时更容易区分：
- Kodi UI / 路由问题
- 汽水上游接口变化
- 登录态问题
- 视频真实播放地址问题

等实机跑稳定后，再决定是否把更多接口直接移进 Kodi 插件，减少对桥接进程的依赖。

## Windows + Kodi 同机测试

1. 进入 `kodi-qishui/bridge/`
2. 双击 `start_windows.bat`
3. 保持窗口运行，默认地址为 `http://127.0.0.1:3300`
4. 执行 `python build_zip.py`
5. Kodi -> 插件 -> 从 ZIP 安装：
   `dist/plugin.video.qishui.music-0.1.0.zip`
6. 打开插件 -> 检查桥接服务
7. 扫码登录
8. 先测试“听歌视频”
9. 再测试搜索 / 我的歌单 / 我的收藏

扫码流程按当前上游要求，通常要使用**已登录的抖音 App**确认。

## 电视盒子 + 电脑桥接

电脑运行 bridge，Kodi 插件设置里的 `qishui-api 地址` 改成电脑局域网 IP：

`http://192.168.1.20:3300`

不要把桥接服务直接暴露到公网。

## 当前需要重点实测的地方

1. 扫码确认后 sessionid 是否能在你的汽水账号正常读取个人资源。
2. `听歌视频` 返回的 video id 是否都能通过 `/video/detail` 拿到真实视频地址。
3. 不同视频返回结构里播放 URL 字段是否一致。
4. Kodi 对汽水 CDN 的 MP4/HLS/DASH 直播放兼容性。
5. 搜索接口是否需要额外 PC 签名 header。

0.1 的目标不是先堆功能，而是把“**登录 -> 听歌视频 -> 点开直接播**”这条主链路跑通。
